# プロダクト計画：販売・複製・在庫独立化ロードマップ

作成日: 2026-09-14
目的: 本在庫管理システムを「完成版」として複製・販売できるようにするための段階計画。

---

## 背景・要件（オーナー方針）

- 本アプリを完成させ、**複製して販売**したい。
- 販売時の懸念: 顧客の管理者が「在庫を跨ぐ/跨がない」設定を誤り、在庫がおかしくなる → クレーム。
  → 在庫仕様は**運営者（オーナー）が管理する総括ページ**で切り替え、顧客管理者には触らせない方針。
- 在庫の基本ルール: **カテゴリー内で同一品番は在庫共有可、カテゴリーを跨いだ在庫共有はしない**（独立）。
  ただし現行Verの共有動作も残し、**共有/独立を切替式**にする。

---

## 「複製」の2種類（明確に区別）

### A. カテゴリー複製（1アプリ内・データ複製）
- 1つのアプリ内でカテゴリー配下(ジャンル/ユニット/パーツ/展開図/在庫)を複製するだけ。
- 管理ページ・ユーザーページは既存のものがそのまま両方に反映（ページ複製は不要）。
- 例: GT3-049 → GTR-GT3 Rev.4.1。

### B. アプリ丸ごと複製（販売用・インスタンス複製 / マルチテナント）
- 顧客ごとにアプリ(管理＋ユーザー＋DB)を1セットとして複製・提供。
- 実現方式は2案:
  - **マルチテナント型**: 1アプリ・1DBで tenantId により顧客分離（1回デプロイで複数顧客）。
  - **インスタンス複製型**: 顧客ごとに 別Neon + 別Cloud Run + 別Vercel を発行。
- 運営者総括ページから顧客インスタンスの発行・仕様(在庫モード等)設定を行う。

## 現在の設計上の制約（フェーズ2で対応）

- 現行 `PartMaster.partNumber` は **グローバル一意**で、在庫は全カテゴリー共有が前提。
  → perCategory対応のため categoryId を導入し (categoryId, partNumber) で一意化する。
- 在庫を参照/更新する箇所: partService(create/update/updateStock/getAll/getByGenre),
  inventoryCountService, statsService, searchService, exportService, partController。
  これらを stockMode で分岐する。
